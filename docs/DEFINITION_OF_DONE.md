# Definition of Done и критерии приемки

**A feature is DONE only when**

1. Встроена в настоящую точку входа приложения и доступна по UI/маршруту.
2. Взаимодействие работает на реальном разрешённом API или **однозначно** помечено как fixture-only preview (не выдаётся в prod).
3. Есть loading/loaded/empty/error/offline/permission states и retry там, где уместно.
4. Все кнопки имеют действия и accessible label, 44pt tap region, не блокируют back gesture.
5. Есть реальные проверки/хотя бы smoke test с записанным результатом, а не «кажется норм».
6. Изменения не ломают работающие модули. Имеется evidence Xcode build или указанный blocker.
7. Светлая/тёмная, Dynamic Type, iPhone sizes проверены (для P0 обязательно).

## Minimal release gate

- P0 100% функционально готовых или формально исключенных по недоступности API функций с согласованным fallback.
- Нет известного severity-1 crash/data loss/auth leak. Severity-2 критические UX bugs решены или documented release blocker.
- Unit & UI test results фактические, warning drift документирован.
- Всё, что взято из сторонних источников, с лицензией/правом использования и исходной ссылкой.
- Папка `output/` содержит честные результаты; `NOT RUN` никогда не превращается в `PASS`.

## Checklist перед финальным ответом агента

- [ ] Изучен реальный Xcode-проект; SHA/ветка зафиксированы.
- [ ] Ветка/коммиты не теряют оригинальную бизнес-логику.
- [ ] Таблица экранов отражает actual status и API access.
- [ ] Были реальные сборки + тесты или явно записан blocker.
- [ ] Есть screenshots хотя бы P0 в светлой/тёмной теме.
- [ ] Названы ограниченные VK функции (особенно audio/messages).
- [ ] Не скопирован непроверенный Fenrir GPL/README-код или чужие секреты.
- [ ] Финал содержит точный список незавершённых задач, не заявляет zero bugs.
