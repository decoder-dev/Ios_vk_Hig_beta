# VK Native — iOS 27 / Apple HIG — Cursor Implementation Kit

**Версия:** 1.0 · **Подготовлено:** 02.11.2026 · **Язык:** русский · **Назначение:** передать автономному агенту Cursor полное ТЗ и визуальную базу для разработки VK-клиента на iOS.

**Компактная версия:** фотоборды и 16 экранных кропов сохранены в JPEG высокого качества (92, 4:4:4) без изменения разрешения. Это позволяет уложить ZIP в 4 МБ; технические документы, SVG, исходные примеры и правила агента не сокращены.

## Что внутри

Это **не собранное приложение**, а профессиональный handoff-пакет: четыре дизайнерских фотоборда (16 визуальных референсов), отдельные кропы, набор схематичных SVG-экранов, экранный реестр, подробные описания, правила Cursor, главный промпт, SwiftUI reference snippets, фикстуры API, требования к QA/безопасности, последовательность внедрения и журнал прогресса.

**Важно:** визуальные изображения — концептуальные ИИ-эскизы, не точные Apple-скриншоты и не готовый исполняемый UI. Текст на них может содержать ошибки, а авторские размеры элементов нужно уточнять по спецификациям. **Ни один внешний Android-репозиторий и ни один действующий iOS-репозиторий пользователя не вложен**. Реальная сборка и прогон XCTest в данном пакете не выполнялись. Cursor должен работать с реальным Xcode-проектом пользователя, а не создавать фальшивые отчёты.

## Быстрый запуск для Cursor

1. Сделайте резервную копию (ветку Git) вашего iOS-проекта. Распакуйте **содержимое ZIP напрямую в корень** рабочего проекта (не во вложенную папку). `.cursor/rules` и `AGENTS.md` должны оказаться в корне репозитория.
2. Откройте корневую папку проекта в Cursor. Включите Agent. Откройте `PROMPT_FOR_CURSOR.md`, вставьте его в чат с агентом и приложите контекст `@README_START_HERE.md @docs/SCREEN_SPECS.md @docs/FEATURE_MATRIX.csv @design/boards` по возможности.
3. Если у вас пока **нет iOS-репозитория**, передайте агенту инструкцию создать Xcode-проект с нуля, используя `examples/SwiftUIReference` как отправную точку, **после проверки** `project.pbxproj`, установленного SDK и доступности API.
4. Агент сперва проводит аудит фактической структуры и API (файл `output/REPO_AUDIT.md`), затем ведёт `output/IMPLEMENTATION_STATUS.md`, `output/API_CAPABILITIES.md`, `output/TEST_RESULTS.md` и `output/BLOCKERS.md`.
5. Проверяйте реальную Xcode-сборку и симулятор. На Linux или Windows нельзя честно заявлять, что приложение собрано в Xcode, без macOS/Xcode среды или подключённого macOS runner.

## Главные папки

- `PROMPT_FOR_CURSOR.md` — единый управляющий промпт для Cursor.
- `AGENTS.md`, `.cursor/rules/*.mdc` — постоянные правила агента.
- `docs/` — Apple HIG, архитектура, UX, API, приёмка, лицензии, риски и исследования.
- `docs/SCREEN_SPECS.md` и `docs/FEATURE_MATRIX.csv` — весь фронт работ в разрезе экранов и состояний.
- `design/boards/` — 4 концепт-борда, по 4 iPhone на каждом.
- `design/screens/` — отдельные иллюстрации экранов, обрезанные из бордов (для ориентира).
- `design/wireframes/` — 30+ чистых SVG-макетов с одинаковыми координатами и русскими подписями.
- `design/preview.html` — открываемая локально галерея: борды и переходы к файлам.
- `design/tokens.json` — согласованная токенизация с оговоркой о системной динамической цветовой схеме.
- `examples/SwiftUIReference/` — наброски SwiftUI-компонентов и UI в коде, **не** вместо интеграции с настоящими репозиториями.
- `examples/Fixtures/` — вымышленные данные для preview и тестов.
- `scripts/` — аудит / проверки для целевой macOS-машины и отчёты.
- `output/` — шаблоны отчётов Cursor; редактируйте по мере работы.

## 7 условий успеха

1. Каждая реально доступная функция маппится на кнопку, экран или честно объяснённое ограничение.
2. Нативный дизайн: крупные заголовки, SF Symbols, системные материалы, настоящие NavigationStack/TabView, безопасные отступы.
3. Чаты и лента работают на реальном API **только с разрешёнными эндпоинтами и выданными scope**; запрет на обход авторизации.
4. Реальные данные, ошибки, загрузка, пустые экраны и нет сети отрисовываются стабильно.
5. Все основные жесты доступны и через VoiceOver; все touch-target не меньше рекомендованных 44×44pt.
6. Прогоны unit/UI tests + доступные размеры устройств + dark/light + Dynamic Type.
7. Результат — **собранный и протестированный** в доступной среде проект или точный список блокеров. Никаких «всё работает» без логов.
